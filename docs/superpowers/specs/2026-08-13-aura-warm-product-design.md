# Aura 温暖产品式前端设计

## 目标

将 Aura 从“紫色 SaaS/AI 技术演示”转为一个有温度、适合日常使用的个人穿搭空间。页面以展示和功能为主，但采用车企官网式的“场景展示 → 逐层解释 → 进入操作”节奏，不使用看板、ECharts 或高密度后台面板。

本轮只改变前端表现层和页面叙事，不改变后端 API、数据模型和核心业务能力。

## 设计原则

1. 生活感优先：真实衣物、穿搭图片、布料和日常场景是视觉主角。
2. 一屏一重点：每个区块只承担一个主要信息或动作。
3. 功能逐层展开：先展示结果，再解释原因，最后提供编辑、收藏和调整。
4. AI 隐形化：用户看到的是造型建议和自然语言，不看到模型、工具调用、参数和运行日志。
5. 统一而克制：减少卡片、阴影、渐变和高饱和色，保留充足留白与明确层级。

## 视觉系统

### 色彩

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#F5F1EA` | 亚麻暖白 |
| 表面 | `#FFFDFC` | 柔和白，用于浮层和输入区 |
| 主文字 | `#2E2A26` | 深棕黑，替代纯黑 |
| 次要文字 | `#81786E` | 暖灰 |
| 主强调 | `#68705A` | 柔和橄榄绿，主要操作 |
| 辅助强调 | `#A98570` | 陶土色，用于生活感提示 |
| 边框 | `#E5DED4` | 低对比淡米灰 |

禁止将紫色、霓虹渐变或 Instagram 渐变作为全局品牌色。局部内容图片可以自然出现其他颜色，但 UI chrome 必须维持暖中性基调。

### 字体与排版

- 中文使用系统中文字体栈；英文使用系统无衬线字体，优先选择 Inter/Avenir 风格。
- 标题使用较大字号、较轻字重和舒适行距；正文避免过度压缩。
- 页面标题、区块标题、说明文字和操作文字形成明确的三级层级。
- 单屏避免同时出现多个大标题和多个同等强度的 CTA。

### 形状、边框与阴影

- 大区块使用 16–24px 的柔和圆角；小控件使用 8–12px，避免所有元素胶囊化。
- 优先使用细边框表达层级，阴影只用于浮层、抽屉和需要脱离背景的对象。
- 不使用厚重侧边栏、密集卡片网格和玻璃拟态。

### 图片比例

- 主视觉：宽幅 16:9 或接近全屏，用于场景和整套穿搭。
- 搭配结果：4:5，用于人物和完整造型。
- 单品：3:4，保留服装完整轮廓。
- 场景横幅：宽幅图，作为区块之间的节奏转换。

## 信息架构与页面叙事

### 全局导航

桌面端从固定后台侧边栏改为轻量顶部导航：

```text
Aura     首页    衣橱    造型师                         用户
```

导航保持暖白半透明和低对比边界。当前页面用细线或柔和底色标记。用户头像保留个人入口，AI 页面命名为“造型师”，不使用“Agent”。移动端使用简化顶部导航和可访问的底部入口。

### 首页：今日穿搭

首页采用纵向叙事，不再以瀑布流和统计卡片作为第一屏。

1. **今日主视觉**：整套穿搭或生活场景占据主要空间；左侧为短文案、天气/场合/风格摘要，提供“查看搭配”和“让 Aura 换一套”。
2. **为什么适合你**：用三段短说明解释温度、个人风格和衣橱可获得性。点击说明后展开细节，不显示复杂评分图表。
3. **搭配拆解**：将整套造型拆为外套、上衣、下装、鞋履、配饰等单品。每件单品支持查看、替换、收藏和编辑。
4. **场景切换**：使用横向场景选择，如通勤、周末、约会、出行。切换时主图和文案交叉淡入，保留当前滚动位置和上下文。
5. **AI 调整入口**：用自然语言邀请进入造型师，例如“让 Aura 把这套搭配变得更轻松一点”。进入后携带当前搭配上下文。

首页仍可以使用现有推荐和图片数据作为内容来源，但视觉组件不应再暴露“Trending”“AI Picks”等看板式统计作为主要内容。

### 衣橱：从管理表格变成可浏览的衣橱

保留现有增删改、分类、搜索和编辑能力，但视觉上采用“分类展示 → 单品浏览 → 单品详情”的层级：

- 顶部使用大幅分类入口和数量简述，避免五个同等权重的统计卡片。
- 单品以 3:4 图片和名称为主，元数据收进详情抽屉或展开区域。
- 添加和编辑保留表单功能，但表单采用暖白浮层、明确分组和低密度布局。
- 后端不可用的本地兜底数据可以继续作为开发体验，但必须和正式数据状态区分，不能伪装成已同步。

### AI 造型师：私人顾问空间

AI 页面从 MaaS 控制台改为“当前搭配 + 私人咨询”：

- 进入时展示当前搭配、涉及单品和可直接点击的需求，如“更正式”“更保暖”“加入一点颜色”。
- 对话采用宽松纵向排版；用户消息和 Aura 回复使用低对比背景或轻边界，不使用高饱和气泡。
- 每次推荐结果紧跟一张可操作的搭配卡，提供“穿这套”“换一个方向”“保存到衣橱”等动作。
- 右侧 Context/Inspector 改为“当前搭配”抽屉，显示图片、场景、单品和收藏/保存操作。
- 技术字段 `Agent`、模型选择、Temperature、Max Tokens、System Prompt、Tool Call、Run Status 不进入普通用户主流程；若保留，应迁移到独立高级设置。
- SSE 的加载、错误和取消状态继续保留，但使用用户语言和可访问状态反馈，例如“正在调整搭配”“连接中断，可以重试”。

## 动效与响应式

只使用服务于层次表达的动效：

- 主视觉和区块进入时淡入并轻微上移。
- 首页整套搭配拆解为单品时使用平滑过渡。
- 场景切换使用图片与文案交叉淡入。
- AI 推荐替换时突出发生变化的单品，避免全屏闪烁。
- 尊重 `prefers-reduced-motion`，关闭非必要过渡。

响应式规则：

- 桌面端突出宽幅图片与双栏详情。
- 窄屏将双栏内容变为纵向流，并将当前搭配详情改为抽屉/底部面板。
- AI 输入始终保持可见，不能被侧栏或视觉内容挤出屏幕。
- 图片、文字和按钮必须保持足够的触控尺寸与对比度。

## 实施边界

### 第一轮

1. 替换全局色彩、字体、间距、圆角、边框和导航样式。
2. 重做首页叙事结构和主视觉层级，保留现有推荐数据、喜欢/收藏和刷新逻辑。
3. 重做 AI 造型师的用户层 UI，保留现有聊天 store、SSE 解析和 MaaS 组件的数据能力。
4. 将衣橱页面迁移到同一套视觉 token，保留增删改、搜索和分类逻辑。
5. 不在本轮新增后端接口，不引入图表库或复杂滚动引擎。

### 验收标准

- 首页首屏不出现统计看板、ECharts 或技术状态面板。
- 首页、衣橱和造型师使用同一套暖中性色、字体、间距和交互状态。
- 用户可从首页搭配上下文进入 AI 造型师，并能看到当前搭配信息。
- 现有衣橱和对话核心操作保持可用。
- 桌面端和移动端均无横向溢出，抽屉可打开和关闭。
- `npm run build` 通过，且修复当前 `AgentWorkspace.vue` 的 TypeScript 错误。
- 认证 token key 在全局统一，开发 mock 与真实 API 状态明确区分。

## 未纳入本轮

- 新增推荐算法、后端接口或数据模型。
- 复杂品牌宣传片级滚动动画。
- 3D 衣橱、视频背景或图表分析。
- 完整的设计系统组件库重构。
